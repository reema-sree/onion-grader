# ML Pipeline Data Documentation

This document describes the data organization, labelling guidelines, and dataset preparation steps for the onion grading ML pipeline.

## Dataset Organisation
Expected directory structure:
```
ml/data/
  raw/
    images/          # Original images (.jpg, .png)
    annotations/     # COCO JSON or YOLO txt labels
  processed/
    train/
      images/
      labels/
    val/
      images/
      labels/
    test/
      images/
      labels/
  data.yaml          # YOLO dataset config (auto-generated by prepare_dataset.py)
```

## Labelling Guide
Detailed instructions for annotating the five defect classes:

1. **good** - Healthy onion with intact skin, no visible damage, no sprouting. Uniform color (golden, red, or white depending on variety). Firm texture visible.

2. **damaged** - Onion showing physical damage: cuts, bruises, pressure marks, peeling outer skin, insect damage, or mechanical harvesting damage. Partially crushed or deformed onions.

3. **rotten** - Onion showing signs of rot/decay: dark discoloration, soft/mushy spots, mold growth, fungal infection, bacterial wet rot. Black mold (Aspergillus niger) or neck rot (Botrytis).

4. **sprouted** - Onion with visible green sprouts emerging from the top. Any stage of sprouting counts, from just breaking through to fully elongated sprouts.

5. **undersized** - This class is determined by the calibration system, not by visual labelling. During annotation, label small-looking onions as 'good' if they have no defects. The size classification happens at inference time using the marker-based calibration system.

## Photo Collection Rules
- **Background**: Use a plain, non-reflective background (white or light grey preferred). Avoid patterned surfaces.
- **Reference marker**: ALWAYS include a reference marker in the frame - either a standard Indian coin (₹1 = 2.5cm diameter, ₹2 = 2.6cm, ₹5 = 2.3cm) or a printed calibration card of known dimensions.
- **Lighting**: Capture under varied lighting - natural daylight, fluorescent, LED. Avoid harsh shadows. Include some challenging lighting to improve model robustness.
- **Arrangement**: Spread onions out so they don't overlap heavily. Mild touching is OK but heavy occlusion should be avoided.
- **Camera**: Capture from directly above (bird's eye view) at 30-50cm distance. Use phone camera in full resolution.
- **Variety**: Include different onion varieties (red, white, golden), different sizes, and different stages of each defect.
- **Quantity**: Aim for 5-20 onions per image.
- **Resolution**: Minimum 1280x720px. Higher is better.

## Annotation Format
- Use COCO JSON format (preferred) or YOLO segmentation format
- For COCO JSON: polygon annotations for each onion instance
- For YOLO txt: `class_id x1 y1 x2 y2 ... xn yn` (normalized polygon coordinates)
- Class IDs: 0=onion, 1=marker (for segmentation stage)
- Defect class labels are applied as attributes or in a separate classification annotation

## YOLO Classes (Segmentation Stage)
| ID | Class |
|----|-------|
| 0  | onion |
| 1  | marker |

## Defect Classes (Classification Stage)
| ID | Class | Visual Cues |
|----|-------|-------------|
| 0  | good | Intact, uniform color, no damage |
| 1  | damaged | Cuts, bruises, peeling, deformation |
| 2  | rotten | Dark spots, mold, soft decay |
| 3  | sprouted | Green sprouts visible |
| 4  | undersized | Size-based (determined by calibration, not visual) |

## Public Datasets & Attribution

### Primary Dataset (Selected)

**Roboflow – Instance Segmentation (wagk9)**
- URL: <https://universe.roboflow.com/yolo-custom-object-detection/instance-segmentation-wagk9>
- Task: Instance segmentation
- Workspace: `yolo-custom-object-detection`
- Project ID: `instance-segmentation-wagk9`

#### Download via Roboflow Python SDK

```bash
pip install roboflow
```

```python
from roboflow import Roboflow

rf = Roboflow(api_key="YOUR_ROBOFLOW_API_KEY")
project = rf.workspace("yolo-custom-object-detection").project("instance-segmentation-wagk9")
version = project.versions()[0]                    # latest version
dataset = version.download("yolov8")               # downloads in YOLOv8 format
# dataset.location holds the path to the downloaded data
```

Or use the helper script provided:

```bash
python ml/download_dataset.py --api-key YOUR_ROBOFLOW_API_KEY --format yolov8
```

After downloading, the data goes into `ml/data/raw/` and you run `prepare_dataset.py` as usual.

> **Attribution**: Dataset sourced from Roboflow Universe. Comply with the dataset's license as published on its Roboflow page.

### Additional / Supplementary Datasets

1. **Custom Collection** – Collect and annotate your own images following the photo‑collection rules above. Recommended for Indian onion varieties and specific defect coverage.

2. **Roboflow Universe** – Search for "onion detection", "onion segmentation", or "onion quality" for additional data. Always verify license terms.

3. **Kaggle** – Search for "onion classification" or "vegetable quality grading". Note: most are classification‑only (no masks) and may need re‑annotation.

4. **COCO Dataset** – Useful for transfer‑learning the segmentation backbone, though it has no onion‑specific classes.

> **Important**: Always verify the license of any public dataset before use. Provide proper attribution. Do not use restrictively‑licensed datasets in commercial applications without permission.

## Getting Started
1. Download the primary dataset with `python ml/download_dataset.py --api-key YOUR_KEY`
2. (Optional) Add your own images following the photo‑collection rules above
3. Annotate any new images using LabelMe, CVAT, or Roboflow (export as COCO JSON)
4. Place raw data in `ml/data/raw/`
5. Run `python -m ml.prepare_dataset --input-dir ml/data/raw --output-dir ml/data/processed`
6. Run `python -m ml.train --data ml/data/processed/data.yaml`

## Notes
- Never train on synthetic or made-up data and report those metrics as real
- Always clearly label mock/synthetic results
- The calibration system uses the reference marker to convert pixel measurements to real-world cm
- The grading rules (Grade A vs URS thresholds) are defined in `backend/config/grading_rules.yaml`, not in the ML pipeline
